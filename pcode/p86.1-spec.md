# P86.1 — abstract machine spec (draft, 2026-10-14)

Target of the Small-C compiler; translated to 8086 assembly (A86 syntax) as a DOS .COM file. Status: **superseded 2026-10-22 by PCODE86.2** (two-accumulator p-code, see `pcode86.2-spec.md`). Kept for reference; frame layout, SYS services and C-level design decisions carry over.

## Machine model
- 16-bit words, little-endian.
- One flat 64K byte-addressed data space (tiny model). The stack lives in it, so `&local` is a real address.
- Stack grows **down** (as on the 8086).
- Registers: `PC`, `SP`, `FP`, `R` (return value; maps to `AX`).
- All arithmetic wraps mod 65536.

## Encoding
- One opcode byte; **bit 7 set ⇒ a 16-bit little-endian operand follows.** Instruction length is known from that bit alone.
- `00` reserved: illegal-op trap. Free for P86.2: `1B–7F`, `89–FF`.
- Jump/call targets are absolute code addresses.

## Notation
```
… a b → … r     stack picture; top is rightmost
POP             r = W[SP]; SP = SP + 2
PUSH(x)         SP = SP − 2; W[SP] = x
W[x], B[x]      word (little-endian) / byte at data address x
s(x)            x read as signed (two's complement)
```

## Opcodes (35)

### No operand
| Hex | Op | Operation |
|---|---|---|
| 01 | LDW | a ← POP; PUSH(W[a]) |
| 02 | LDB | a ← POP; v ← B[a]; PUSH(sign-extend v) |
| 03 | STW | v ← POP; a ← POP; W[a] ← v; PUSH(v) |
| 04 | STB | v ← POP; a ← POP; B[a] ← v & 0xFF; PUSH(low byte of v, sign-extended) |
| 05 | DUP | PUSH(W[SP]) |
| 06 | DROP | POP |
| 07 | ADD | b ← POP; a ← POP; PUSH(a + b) |
| 08 | SUB | PUSH(a − b) |
| 09 | MUL | PUSH((a × b) mod 65536) — one op for signed and unsigned |
| 0A | DIV | signed, truncates toward 0; TRAP if b = 0 or (a = 0x8000 and b = 0xFFFF) |
| 0B | DIVU | unsigned; TRAP if b = 0 |
| 0C | MOD | signed remainder, sign of dividend; traps as DIV |
| 0D | MODU | unsigned remainder; traps as DIVU |
| 0E | AND | a & b |
| 0F | OR | a \| b |
| 10 | XOR | a ^ b |
| 11 | SHL | n ← POP; a ← POP; PUSH(n ≥ 16 ? 0 : a << n) |
| 12 | SHR | logical; n ≥ 16 ? 0 : a >> n (zero-filled) |
| 13 | SAR | arithmetic; n ≥ 16 ? (s(a) < 0 ? 0xFFFF : 0) : sign-filled shift |
| 14 | EQ | PUSH(a = b ? 1 : 0) |
| 15 | LT | PUSH(s(a) < s(b) ? 1 : 0) |
| 16 | LTU | PUSH(a < b ? 1 : 0) — pointer comparisons |
| 17 | CALLI | t ← POP; PUSH(PC); PC ← t — function pointers |
| 18 | RET | SP ← FP; FP ← POP; PC ← POP |
| 19 | RETV | R ← POP; then RET |
| 1A | PUSHR | PUSH(R) |

### 16-bit operand
| Hex | Op | Operation |
|---|---|---|
| 80 | LIT n | PUSH(n) — also global and function addresses |
| 81 | LLA n | PUSH(FP + n) — n signed: locals negative, args positive |
| 82 | JMP L | PC ← L |
| 83 | JZ L | t ← POP; if t = 0: PC ← L |
| 84 | JNZ L | t ← POP; if t ≠ 0: PC ← L |
| 85 | CALL L | PUSH(PC); PC ← L |
| 86 | ENTER n | PUSH(FP); FP ← SP; SP ← SP − n |
| 87 | ADJ n | SP ← SP + n — caller pops args |
| 88 | SYS n | runtime service n (see below) |

### Design decisions
- **Stores push their value** (C assignment is an expression: `a = b = c`). Statements end in `DROP`; a peephole pass removes the waste.
- **STB pushes the byte actually stored, sign-extended**, so `i = c = 300` gives 44. For `unsigned char` follow with `LIT 255, AND` (same as loads).
- **Plain `char` is signed** (as Turbo C). No `LDBU`: unsigned-char loads are `LDB, LIT 255, AND`.
- **Shift counts ≥ 16 are defined** (C leaves them undefined).
- **Return value in `R`, not on the stack**, so args and result don't collide. `R` is live only between `RETV`/`SYS` and the next `PUSHR`; only `ADJ` may come between. After a void function `R` is undefined.
- Removed from the 45-op draft: `NEG`, `NOT`, `GT GE LE` (+ unsigned), `NE`, `LDBU` — all expressible (C leaves operand evaluation order unspecified, so `a > b` may compile as `b < a`).

## Frame layout (same as an 8086 BP frame)
```
FP+6   second arg
FP+4   first arg
FP+2   return address
FP+0   caller's FP
FP-2   first local
FP-n   last local     ← SP after ENTER n
```
- Args pushed **right to left**, caller pops with `ADJ` (cdecl) — varargs need nothing extra.
- `RET` discards locals and leftover temporaries; afterwards SP is where it was before `CALL`, args still in place for the caller's `ADJ`.

Worked call, `x = add(1, 2);` with `int add(int a, int b) { return a + b; }`:
```
add:  ENTER 0
      LLA 4
      LDW
      LLA 6
      LDW
      ADD
      RETV

      LLA -2       ; &x
      LIT 2        ; args right to left
      LIT 1
      CALL add
      ADJ 4
      PUSHR
      STW
      DROP
```

## SYS services
Same conventions as `CALL`: args stay on the stack (first arg on top), result in `R`, caller does `ADJ` then `PUSHR`. Unknown n: TRAP. Numbers are P86's own, not DOS's, so the same program can run on another host.
```
0 EXIT  (code)            → INT 21h/4Ch   does not return
1 PUTC  (c)               → INT 21h/02h
2 GETC  → c               → INT 21h/08h
3 OPEN  (name, mode) → fd → INT 21h/3Dh
4 CREAT (name) → fd       → INT 21h/3Ch
5 CLOSE (fd)              → INT 21h/3Eh
6 READ  (fd, buf, n) → n  → INT 21h/3Fh
7 WRITE (fd, buf, n) → n  → INT 21h/40h
```
The C runtime (`putchar`, `printf`, `malloc`…) is written in C on top of these — the Forth/Joy/UCSD "small kernel, rest in the language" approach.

## Lowering cheat sheet (C → P86.1)
```
-x         LIT 0, x, SUB
~x         x, LIT -1, XOR
!x         x, LIT 0, EQ
a != b     a, b, EQ, LIT 0, EQ
a > b      b, a, LT
a <= b     b, a, LT, LIT 0, EQ
a >= b     a, b, LT, LIT 0, EQ
uchar load LDB, LIT 255, AND
a += b     &a, DUP, LDW, b, ADD, STW
x++        &x, DUP, LDW, LIT 1, ADD, STW, LIT 1, SUB
a || b     a, JNZ T, b, JNZ T, LIT 0, JMP E; T: LIT 1; E:
```
In `if`/`while` conditions the trailing `LIT 0, EQ` disappears — pick `JZ` or `JNZ`. A signed divide by 2 must **not** become `SAR` (SAR rounds toward −∞, DIV toward 0).

## Program structure
Assembler directives (not opcodes): `.CODE .DATA .BSS`, `DB 'Hello',13,10,0`, `DW 1234`, `RESB n`. Labels `name:` for code and data.

Start-up (crt0) is ordinary P86 at the start of the code:
```
        CALL main
        PUSHR
        SYS 0           ; EXIT(main's result)
```
Compiler emits `LIT 0, RETV` before `main`'s closing brace (C99 5.1.2.2.3: falling off main returns 0).

Hello world:
```
        .CODE
        CALL main
        PUSHR
        SYS 0
main:   ENTER 0
        LIT 15          ; n      (args right to left)
        LIT msg         ; buf
        LIT 1           ; fd = stdout
        SYS 7           ; WRITE
        ADJ 6           ; result unused, so no PUSHR
        LIT 0
        RETV
        .DATA
msg:    DB 'Hello, world!',13,10
```

## Translation to 8086 (A86, .COM)
- `.COM`: `CS=DS=ES=SS`, image at `100h`, DOS sets SP near the segment top. Layout: `100h` crt0 → functions → `__sysN` stubs → `.DATA` → `.BSS` → free → stack.
- Registers: P86 `SP → SP`, `FP → BP`, `R → AX`; scratch `BX CX DX` (MUL/DIV clobber DX).
- Naive mapping first (e.g. `ADD` → `pop bx / pop ax / add ax,bx / push ax`); later cache top-of-stack in AX, then a peephole pass.
- 8086 traps: no `push imm` (186+) — `LIT n` → `mov ax,n / push ax`; `LDW` → `pop bx / push word [bx]` (legal on 8086).
- `SYS n` → `call __sysN`; eight small native stubs, args at `[bp+4]` like any call (`__sys0` reads `[bp+2]` as it never pushes BP; it copies SP to BP because the 8086 can't address `[sp]`).
- **A86 specifics:** default output is .COM at `0100h`; typed variables mean `LIT msg` must emit `mov ax,offset _msg`; mangle C names with `_` (A86 reserves `loop`, `div`, `in`, `byte`…), runtime names `__sysN`; generate unique labels from a counter rather than A86's local labels; directives become emission order.
- **BSS:** DOS doesn't zero memory past the loaded file, so v1 emits `.BSS` as real zero bytes (`db n dup 0`); later crt0 clears it with `rep stosb`.

## Not in v1
`long`, `float`, struct-by-value, `switch` jump tables (compare chains for now), fast local forms `LDL`/`STL` (expected to be ~⅓ of code as `LLA`+`LDW` pairs — first candidates for P86.2).

## Open questions (resolved 2026-10-22 → PCODE86.2)
- Pure stack (as above) vs. accumulator / two-register (Ron Cain's Small-C primary/secondary) vs. register or three-address IR. → two-accumulator p-code, Yuen's pipeline, own expander in C.
- Whether `R` should simply be the top-of-stack cache. → yes: P is the return register.
- Interpreter for P86 (originally planned first, then dropped: compiling to 8086 is the goal). → kept as a test oracle only.
