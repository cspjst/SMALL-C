## When
- Before leaving a chat for a while, before a planned compaction or a new conversation, or when Jeremy says "washup".
- Not as a substitute for writing things down as they happen — a washup catches what slipped through.

## The steps
1. **Welfare first.** Is it a sensible hour; has Jeremy eaten (code of conduct 2)? A washup can wait for dinner.
2. **Check access.** The oracle folder, and delete permission there: create and remove a scratch file under `.git`. Ask again if it has lapsed — it does when the desktop app restarts. **Repeat the test before every git command, `git fetch` included.**
3. **Commit WELFARE's work** as `Claude-SMALL-C-WELFARE`. Stage named paths only — never `git add -A`. Leave other departments' and Jeremy's uncommitted work alone, and their notes too: departments keep their own current (Jeremy, 2026-10-29 19:46: "i prefer as much departmental siloing ... as \"reasonable\""). Jeremy's code (`src/`, `bin/`, `tools/`, `doc/`, `README.md`, `LICENSE`) is his. Mention anything outstanding.
4. **Write the history.** Extend `welfare/SMALL-C-historiography.md` with everything since its last chapter, while the chat still remembers it: the problem, what was tried, what the sources said, what was decided — Jeremy's words quoted and timed, times read from the clock, thin stretches labelled. Other departments' milestones come to WELFARE through the dialogue.
5. **Bring the working agreement up to date:** its Status, Order of work, Pinned and Back burner, so a fresh session can trust them.
6. **Lessons** into the working agreement ("The oracle, commits and pushing"), and into `wakeup.md` anything that changes how a session starts. A lesson that would help every project goes to Jeremy for synergy.
7. **Tidy the dialogue.** Close WELFARE's open entries, or say why they stay open. Corrections are new entries, never edits.
8. **Write the washup handover:** `handover/<date>-welfare-washup.md` — where things stand, what's waiting on whom, anything `wakeup.md` doesn't already say. Short: the documents carry the detail.
9. **Push all** — WELFARE only. Asking for a washup is the word to push (Jeremy, in synergy, 2026-10-29 19:38: "yes washup implies push all"). Fetch first: if GitHub has commits the oracle hasn't (Jeremy's from another machine, a collaborator's merged pull request), bring them in before pushing. Record the push in the dialogue with the hash.
10. **Refresh the project's copies** at the paths its Instructions use, from the oracle — any department's documents that changed, not just WELFARE's. Copying isn't editing.
11. **Verify.** Read every write back and compare checksums; the oracle, GitHub and the project agree; no `.lock` files are left.
12. **Tell Jeremy** the one line that starts the next session: *"WELFARE. Read wakeup.md in ~/dosbox/cspjst/SMALLC and follow it."*
